# ★ Адвент-календарь

Интерактивный адвент-календарь на Next.js 14 (App Router), TypeScript, Tailwind и Supabase (Postgres, Auth, Storage). Интерфейс только на русском, без переключателя языка.

> **Статус:** код написан, но ещё не собирался. Сначала выполните `npm install && npm run typecheck && npm run build` и поправьте возможные мелкие ошибки типов. Кликабельный прототип лежит в `prototype.html`.

## 1. План продукта

| Этап | Состав |
|---|---|
| **MVP (этот репозиторий)** | Календарь из 24 дверец, открытие дней на сервере, задания, заметки/файлы/отметка о выполнении, гостевой режим с переносом прогресса, вход по ссылке из письма и через Google, публикация в галерею или по ссылке с Open Graph, лайки и комментарии, админка (задания, расписание, принудительное открытие/закрытие, пользователи, аналитика), экспорт и удаление данных (GDPR) |
| v1.1 | Ограничение частоты запросов (Upstash), модерация комментариев, жалобы, напоминания по почте |
| v1.2 | Несколько календарей, режим команды/класса, серии и значки, сжатие изображений |

**Допущения (ответов на уточняющие вопросы не было):** один общий календарь; по выходным дверец нет; администратор задаёт дату старта, часовой пояс и число дней; день открывается в 00:00 по часовому поясу календаря (или посетителя, если включено); гости не могут загружать файлы и публиковать; сроки заданий мягкие (показываются, но не блокируют); первый администратор назначается SQL-запросом; комментарии плоские, без модерации.

## 2. Дизайн и картинки на карточках

- Нежная пастельная тема: сливочный фон с «посыпкой», белые округлые панели, розовые кнопки-конфеты, шрифты Comfortaa и Nunito (оба с кириллицей). Цвета заданы в `tailwind.config.ts`.
- Карточка похожа на полароид: квадратное окошко для картинки, наклейка с числом даты, подпись. Закрытый день выглядит как подарок с бантом (в нём нет ни картинки, ни текста), открытый показывает картинку, выполненный получает значок-галочку. Если картинки нет, видно пунктирное «место для картинки».
- Картинку для карточки задаёт администратор в форме задания: ссылка или загрузка файла (`tasks.cover_url`, до 5 МБ, публичный бакет `publication-media/covers/`). Для закрытых дней ссылка на картинку на клиент не отдаётся.

## 3. Архитектура и ключевые решения

- **Открытие дня проверяется только на сервере.** У таблицы `tasks` включён RLS без публичных политик, поэтому анонимный ключ не читает содержимое заданий. Страницы и роуты читают задания через service role в `getDayContext()` (`src/lib/calendar.ts`) и отдают контент только открытым дням. В HTML закрытых карточек нет ни названия, ни текста.
- **Часовые пояса:** `dayUnlockAt(startDate, day, tz)` считает местную полночь через `Intl` с двойным проходом, устойчивым к переходу на летнее время. Проверено для UTC, Москвы, Нью-Йорка, Калькутты и перехода в Берлине.
- **Порядок проверки:** `force_lock`, затем `force_unlock`, затем дата. Обычным пользователям также нужны `is_published` и `publish_at <= now`; администраторы видят черновики.
- **Гость → аккаунт:** гость пишет в `localStorage`; после входа `GuestSync` отправляет данные в `/api/progress/merge` (выполненное побеждает, более новые заметки побеждают, закрытые дни игнорируются), затем очищает хранилище.
- **Загрузки:** клиент запрашивает `/api/upload`, сервер проверяет вход, открытость дня, MIME и размер и выдаёт подписанный токен. Файлы идут прямо в хранилище в папку `{userId}/{taskId}/`. Приватные файлы отдаются по подписанным ссылкам на 60 секунд (`/api/files`).
- **Медленный мобильный интернет:** почти всё рендерится на сервере, нет веб-шрифтов и UI-библиотек, картинки ленивые, заметки сохраняются с задержкой.
- **Без выходных:** настройка `skip_weekends` (включена по умолчанию) убирает субботу и воскресенье: дверцы нумеруются только по будним дням, а выходные просто пропускаются (`dayYmd()` в `src/lib/time.ts`). Если дата старта выпала на выходной, день 1 откроется в понедельник. Для 24 дверец календарь займёт около пяти недель. На карточках показаны номера дат (1, 2, 3, 4, 7, 8…), сетка идёт по неделям пн–пт, поэтому пропуски видны сами. Внутри системы дверцы нумеруются подряд (`tasks.day` = 1…N, это же номер в URL `/day/5`), а дату для каждой считает `dayYmd()`.
- **Режим `tz_mode = user`** открывает дни по часовому поясу посетителя. Можно выбрать ранний пояс и открыть дверцу почти на 14 часов раньше. По умолчанию используется `calendar`, где этого нет.

## 4. Схема БД

См. `supabase/migrations/001_init.sql` (таблицы, RLS, представления, бакеты, 24 тестовых задания на русском).

```
settings(id=1, start_date, timezone, total_days, tz_mode, skip_weekends)
profiles(id→auth.users, email, display_name, role[user|admin])
tasks(id, day UNIQUE, title, description, instructions, media_url, media_type, cover_url, link_url,
      deadline, publish_at, is_published, unlock_override[force_unlock|force_lock])
user_task_progress(user_id, task_id, status, notes, files jsonb, completed_at)  UNIQUE(user_id, task_id)
publications(id, user_id, task_id, slug UNIQUE, content, media_url, is_public)  UNIQUE(user_id, task_id)
likes(user_id, publication_id) · comments(id, publication_id, user_id, body)
events(user_id?, task_id, type[open|complete|share])  → представления task_stats, user_summary (только service role)
```

`is_public = true` показывает публикацию в галерее. Любая публикация доступна по своей ссылке, но страницы «только по ссылке» закрыты от индексации.

## 5. API

| Маршрут | Кто | Назначение |
|---|---|---|
| `PUT /api/progress/[day]` | пользователь | Сохранить статус, заметки, файлы (с проверкой открытия дня) |
| `POST /api/progress/merge` | пользователь | Перенести гостевой прогресс |
| `POST /api/upload` | пользователь | Подписанный токен загрузки |
| `GET /api/files?path=` | владелец/админ | Редирект на подписанную ссылку |
| `POST /api/publications`, `DELETE /api/publications/[id]` | пользователь | Опубликовать, обновить, снять с публикации |
| `POST /api/publications/[id]/like`, `/comments` | пользователь | Лайк, комментарий |
| `POST /api/events` | все | Учёт нажатия «поделиться» |
| `PATCH/DELETE /api/account`, `GET /api/account/export` | пользователь | Имя, удаление, экспорт (GDPR) |
| `POST /api/admin/upload` | админ | Подписанная загрузка картинки для карточки |
| `POST /api/admin/tasks`, `PATCH/DELETE /api/admin/tasks/[id]`, `PATCH /api/admin/settings` | админ | CRUD, расписание, публикация, принудительный режим, настройки |
| `GET /auth/callback`, `POST /auth/signout`, `GET /og` | – | Вход и OG-картинка |

Middleware обновляет сессию и отклоняет межсайтовые изменяющие запросы к `/api`.

## 8. Установка

1. Создайте проект Supabase. В SQL-редакторе выполните `supabase/migrations/001_init.sql`.
2. Auth → Providers: включите **Email** (ссылка из письма) и **Google** (укажите Client ID и Secret). Auth → URL configuration: задайте Site URL и добавьте `https://ВАШ_ДОМЕН/auth/callback` и `http://localhost:3000/auth/callback` в список Redirect URLs.
3. `cp .env.example .env.local` и впишите ключи (Project settings → API).
4. `npm install && npm run dev`
5. Войдите один раз и назначьте себя администратором:
   `update public.profiles set role = 'admin' where email = 'you@example.com';`
6. Откройте `/admin` → «Настройки» и задайте дату старта, часовой пояс и число дней. Задания редактируются на вкладке «Задания».

**Проверка блокировок:** в Админка → Задания выберите в списке «Режим» значение «Открыт» или «Закрыт» для нужного дня. Либо поставьте дату старта на сегодня или раньше.

## 9. Деплой (Vercel)

1. Загрузите репозиторий на GitHub и импортируйте его в Vercel.
2. Добавьте четыре переменные из `.env.example`. `SUPABASE_SERVICE_ROLE_KEY` должен оставаться только на сервере, а `NEXT_PUBLIC_SITE_URL` должен указывать на ваш боевой адрес.
3. Задеплойте, затем обновите Site URL и Redirect URLs в Supabase на боевой домен.

## 10. Безопасность и GDPR

- RLS включён на всех таблицах. Пользователь не может сам повысить свою роль (права на уровне столбца).
- Загрузки ограничены списком MIME-типов и размером и в API, и на уровне бакета. SVG запрещён.
- Пользовательский текст выводится как обычный текст (без `dangerouslySetInnerHTML`). Ссылки в админке должны быть http(s).
- Удаление аккаунта стирает файлы в хранилище, затем пользователя в auth, что каскадом удаляет все строки. Экспорт отдаёт JSON.
- Перед запуском добавьте:
  - ограничение частоты запросов к `/api/*`, особенно для комментариев и загрузок;
  - политику конфиденциальности и уведомление о cookie;
  - модерацию комментариев.
